# Agrobudservices — Webflow → Next.js Migration

## Стек
- Next.js 14+ (App Router), TypeScript, Tailwind CSS
- Деплой: Vercel
- Контент: повністю статичний (без CMS), каталог (4 товари) і блог (2 пости) — TS/JSON у /src/content
- Шрифти: підключати через next/font/local з файлів у /legacy-export/fonts (НЕ через @font-face в CSS)
- Зображення: через next/image, з явними width/height (запобігає layout shift)

## Джерело правди
- Розмітка і контент оригінального сайту: /legacy-export (Webflow HTML export)
- НЕ копіювати баги і проблеми верстки 1-в-1 — оригінал містить проблеми з overflow,
  z-index, responsive поведінкою тощо. Під час перенесення кожної секції їх треба
  знаходити і виправляти самостійно, без окремого списку — оцінювати кожну секцію
  критично, як дизайнер/фронтенд-розробник, що робить сайт заново, а не копію

## Конвенції
- Один компонент = одна логічна секція сторінки (Hero, ProductGrid, ContactForm тощо)
- Спільні елементи (Header, Footer, Nav) — окремі переюзовувані компоненти в /src/components/layout
- Стилі — тільки Tailwind utility classes, кастомний CSS лише коли Tailwind не вистачає
- Усі інтерактивні елементи — перевіряти на overflow/z-index/responsive одразу під час перенесення

## UX/UI покращення (обов'язково при кожній секції)
Окрім точного перенесення функціоналу, активно покращувати UX/UI, не змінюючи бренд і
загальний стиль сайту:
- Плавні transition/hover-стани на кнопках, картках, посиланнях (якщо їх не було)
- Коректні focus-стани для доступності (клавіатурна навігація)
- Достатні touch-таргети на мобільній версії (мінімум ~44px для кнопок/лінків)
- Візуальна ієрархія: перевіряти контраст тексту, відступи (spacing), вирівнювання
- Анімації/переходи між станами не мають бути різкими або "стрибати"
- Забезпечити плавний адаптив без різких зламів layout між брейкпоінтами
- Якщо в оригіналі елемент виглядає переобтяженим чи заплутаним — пропонувати
  простіше рішення, зберігаючи зміст і функціонал

## SEO
- Кожна сторінка має свій метадані-блок (title, description, OG image) через Next.js Metadata API
- Значення брати з <head> відповідного файлу в /legacy-export
- 404.html → not-found.tsx, 401.html → окрема сторінка/обробка помилки доступу

## Форми
- Форма Contact Us (contact-us.html) наразі відправляє заявки на email
- У Next.js реалізувати через API route (/src/app/api/contact/route.ts) + Resend (resend.com) для відправки email
- Потрібно: зареєструвати акаунт на Resend, отримати API key, додати в змінні середовища (.env.local, і пізніше в Vercel Environment Variables)
- Email-адресу отримувача заявок — уточнити у користувача

## Процес перенесення сторінки
1. Відкрити відповідний .html з /legacy-export
2. Витягнути контент, структуру секцій і метадані (title/description/OG)
3. Зверстати заново на Tailwind: точно перенести контент і функціонал, виправити
   проблеми верстки і одночасно застосувати покращення з розділу "UX/UI покращення"
4. Перевірити адаптив на mobile/tablet/desktop
5. Коротко пояснити користувачу, що саме було виправлено/покращено порівняно з оригіналом
